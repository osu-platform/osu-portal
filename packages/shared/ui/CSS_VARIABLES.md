# CSS-переменные портала

Единственная система токенов в проекте. Всё, что красит интерфейс, ходит
через неё — библиотечных префиксов (`--tgui--*`) и старого слоя
(`--portal-theme-*`) больше нет.

Объявления живут в [`src/styles/tokens.css`](src/styles/tokens.css) и
подключаются автоматически вместе с `AppRoot`.

## Правила

1. **`--p-color-*` — цвет, `--p-*` — всё остальное.** Переменных с другими
   префиксами быть не должно.
2. **Цвет в CSS пишется только токеном.** Хардкод `#fff` допустим лишь там,
   где фон не зависит от темы (контент поверх фото, QR-код) — и тогда через
   `--p-color-static-white` / `--p-color-static-black`.
3. **Фон компонента, который «вырезает» подложку, берётся из `--p-surface`,
   а не из `--p-color-bg-primary`.** См. раздел «Контекстная поверхность».
4. Обе договорённости проверяет тест [`scripts/tokens.test.mjs`](../../../scripts/tokens.test.mjs),
   он падает в CI при нарушении.

## Цвета темы

Приходят из пресета или от платформы, задаются на `<html>` через
`ThemeProvider`. Значения в `tokens.css` — фолбэк до старта JS.

### Фоны

| Переменная               | Роль                                                     |
| ------------------------ | -------------------------------------------------------- |
| `--p-color-bg-primary`   | Фон контента — «бумага» под текстом                       |
| `--p-color-bg-secondary` | Подложка, на которой лежат карточки и секции              |
| `--p-color-bg-elevated`  | Приподнятая поверхность: модалки, поповеры, карточки      |

### Текст

| Переменная                  | Роль                                            |
| --------------------------- | ----------------------------------------------- |
| `--p-color-text-primary`    | Основной текст                                  |
| `--p-color-text-secondary`  | Подзаголовки, описания                          |
| `--p-color-text-tertiary`   | Плейсхолдеры, подсказки, недоступные элементы   |
| `--p-color-text-accent`     | Акцентный текст (не ссылка)                     |
| `--p-color-text-danger`     | Текст ошибки                                    |

> Раньше существовали `text-muted`, `text-hint` и `text-header` — три токена
> на две роли. Одинаковые по смыслу элементы красились по-разному, поэтому
> они схлопнуты в `text-tertiary` и `text-primary`.

### Границы

| Переменная                  | Роль                                                        |
| --------------------------- | ----------------------------------------------------------- |
| `--p-color-border-default`  | Заметная граница: обводка полей ввода. Контраст ≥ 3:1        |
| `--p-color-border-subtle`   | Декоративная тонкая граница                                 |
| `--p-color-divider`         | Разделитель элементов списка                                |

### Акцент и действия

| Переменная                         | Роль                          |
| ---------------------------------- | ----------------------------- |
| `--p-color-accent`                 | Основной акцент               |
| `--p-color-link`                   | Ссылки и интерактивный текст  |
| `--p-color-action-primary-bg`      | Фон основной кнопки           |
| `--p-color-action-primary-text`    | Подпись основной кнопки       |
| `--p-color-action-danger-bg`       | Фон деструктивной кнопки      |
| `--p-color-action-danger-text`     | Подпись деструктивной кнопки  |

### Поверхности и статусы

| Переменная                    | Роль                     |
| ----------------------------- | ------------------------ |
| `--p-color-surface-section`   | Фон секции/карточки      |
| `--p-color-surface-header`    | Фон шапки экрана         |
| `--p-color-surface-tabbar`    | Фон нижней навигации     |
| `--p-color-success`           | Статус «успех»           |
| `--p-color-warning`           | Статус «предупреждение»  |
| `--p-color-destructive`       | Статус «ошибка»          |

## Контекстная поверхность

`--p-surface` — цвет поверхности, на которой компонент **фактически лежит**.

Зачем: поле ввода рисует фон под своей меткой, врезанной в рамку. Если брать
`--p-color-bg-primary`, поле всегда рисует «фон приложения» — и внутри
модалки, секции или карточки вокруг него появляется прямоугольник чужого
цвета. Именно так выглядел баг с рамками вокруг селектов.

Как работает: каждый контейнер, который красит свой фон, тут же
переопределяет переменную на собственное значение. Дальше она наследуется
по дереву, поэтому вложенность разбирается сама.

```css
/* Контейнер: покрасил фон — объяви поверхность */
.modal {
  background: var(--p-color-bg-secondary);
  --p-surface: var(--p-color-bg-secondary);
}

/* Компонент внутри: спрашивает, на чём лежит */
.fieldLabel {
  background: var(--p-surface);
}
```

Если нужно, чтобы элемент **отличался** от подложки (заливка поля в
iOS-стиле, вложенная плашка), берётся `--p-color-surface-raised` — он
считается от текущей поверхности, а не от фона приложения, и поэтому
заметен на любой подложке.

## Производные цвета

Вычисляются из токенов темы через `color-mix`, в пресетах их нет — поэтому
они работают и для темы, пришедшей от Telegram.

| Переменная                       | Назначение                          |
| -------------------------------- | ----------------------------------- |
| `--p-color-surface-raised`       | Поверхность выше текущей            |
| `--p-color-surface-hover`        | Наведение                           |
| `--p-color-surface-active`       | Нажатие                             |
| `--p-color-fill-accent`          | Акцентная полупрозрачная заливка    |
| `--p-color-fill-neutral`         | Нейтральная заливка                 |
| `--p-color-skeleton-from` / `-to`| Скелетоны загрузки                  |
| `--p-color-overlay-backdrop`     | Затемнение под модалкой             |
| `--p-color-overlay-inverse-bg`   | Фон подсказок и тостов              |
| `--p-color-focus-ring`           | Кольцо фокуса                       |
| `--p-color-static-white` / `-black` | Контент поверх фото и QR         |

## Не-цветовые токены

Типографика (`--p-text-font-size`, `--p-title1-line-height`, …), начертания
(`--p-font-weight-accent1..3`), слои (`--p-z-simple`, `--p-z-skeleton`,
`--p-z-overlay`), `--p-border-width`, `--p-shadow-section`,
`--p-safe-area-inset-bottom`. Полный список — в `tokens.css`.

## Ветка по схеме

Когда правило зависит именно от светлой или тёмной схемы:

```css
:root[data-p-scheme="light"] .wrapper {
  /* ... */
}
```

Атрибут проставляет `ThemeProvider`. Не полагайтесь на подстроку в
`style`-атрибуте — так было раньше, и это ломалось при любой смене порядка
записи переменных.
