# @portal/shared-theme

Система тем портала: принимает цвета от платформы или выбор пользователя и
раскладывает их в CSS-переменные `--p-*`.

## Задача

Портал запускается в разных оболочках, и каждая сообщает о теме по-своему:

| Источник               | Что даёт                                       |
| ---------------------- | ---------------------------------------------- |
| Telegram Mini Apps     | Палитру `themeParams` + схему, с подпиской на смену |
| Мессенджер MAX         | Только схему — `style="color-scheme: dark"` на документе |
| Браузер                | Только схему — `prefers-color-scheme`          |
| Пользователь           | Один из наших пресетов, опционально с точечными правками |

Пакет сводит это к одному набору семантических токенов, на котором держится
весь интерфейс.

## Как это устроено

```
Выбор пользователя         Платформа (Telegram / MAX / браузер)
        │                             │
   userTheme                    runtimeTheme
        │                             │
        └────────► resolveTheme ◄─────┘
                        │
                 normalizeRuntimeTheme  ← палитра платформы → токены
                        │
                   deriveTokens         ← достраивает недостающее
                        │
              injectThemeVariables      ← запись в CSS-переменные на <html>
                        │
                   --p-color-*
```

### Приоритеты

1. `userTheme.overrides` — точечные переопределения
2. `userTheme.mode` — пресет / произвольная тема / «как в платформе»
3. `runtimeTheme` — тема платформы
4. Пресет по умолчанию (`dark`)

### Что делает нормализация

Платформа почти всегда присылает **неполную** палитру, поэтому:

- недостающие токены выводятся из присланных, а не берутся из чужой темы —
  иначе получается нечитаемая смесь;
- пустые строки и мусор отбрасываются (`""` прошёл бы проверку на
  `undefined` и обнулил бы фон);
- приподнятая поверхность приподнимается принудительно, если платформа
  прислала её равной основному фону (так делает Telegram) — иначе пропадают
  границы карточек и выпадающих списков;
- подпись на кнопке проверяется на контраст: если предложенный платформой
  цвет не дотягивает до 4.5:1, берётся чёрный или белый.

> Последнее — сознательный отход от нативного вида. Штатная синяя кнопка
> Telegram даёт белым текстом 3.7:1; мы предпочли читаемость.

## Использование

### Подключение

```tsx
import { ThemeProvider } from "@portal/shared-theme"
import { useRuntimeTheme } from "@portal/shared-platform"

function App() {
  const runtimeTheme = useRuntimeTheme()
  const { userTheme } = useThemePreferenceState()

  return (
    <ThemeProvider runtimeTheme={runtimeTheme} userTheme={userTheme}>
      <YourApp />
    </ThemeProvider>
  )
}
```

`ThemeProvider` — контролируемый компонент. Он ничего не хранит:
персистентность выбора лежит на внешнем состоянии
(`packages/shell/src/settings/useThemePreference.ts`).

### В стилях

```css
.card {
  background: var(--p-color-surface-section);
  color: var(--p-color-text-primary);
}
```

Полный справочник токенов и правила их применения —
[packages/shared/ui/CSS_VARIABLES.md](../ui/CSS_VARIABLES.md).

### В коде

```tsx
const { tokens, isDark, scheme } = useTheme()
```

Нужно, когда цвет требуется значением, а не переменной: например, Ant Design
прогоняет цвета через свой алгоритм и `var(...)` разобрать не может.

## Пресеты

`dark` (по умолчанию), `light`, `midnight`, `nord`, `latte`.

Все проверены на WCAG 2.1 AA — обычный текст 4.5:1, границы полей и
смысловая графика 3:1. Правила описаны декларативно в
[`src/utils/contrast.ts`](src/utils/contrast.ts), проверка — в
`src/__tests__/presets.test.ts`.

**Меняя цвета в пресете, прогоните `pnpm test`.** Тест назовёт конкретную
пару и недостающий контраст. Чаще всего проваливается `textTertiary` —
это плейсхолдеры полей, самое частое место нечитаемого текста.

## Добавление токена

1. Поле в `ThemeTokens` (`src/types.ts`) и ключ в `TOKEN_KEYS`.
2. Значение во всех пресетах (`src/presets.ts`) — TypeScript подскажет, где.
3. Вывод в `deriveTokens` (`src/utils/normalize.ts`) — что делать, если
   платформа его не прислала.
4. Строка в `:root` в `packages/shared/ui/src/styles/tokens.css` со значением
   из пресета `dark` — тест проверит совпадение.
5. При необходимости — правило в `CONTRAST_RULES`.

CSS-переменная получится автоматически: `bgPrimary` → `--p-color-bg-primary`.

Если значение **выводимо** из других токенов (полупрозрачная заливка,
состояние наведения) — ему не место в пресете. Такие считаются в CSS через
`color-mix` в `tokens.css` и работают для любой темы, включая платформенную.
